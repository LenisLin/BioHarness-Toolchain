# Validation Reference Preparation Completion Verifier Prompt

## Purpose

Read-only verifier for validation reference preparation evidence.

## Acceptance Rules

Accept `REFERENCE_READY` only when the result records reference target discovery evidence, selected primary target, completed acquisition evidence, materialized artifacts, parser or loader summary, and files written. For long-running generated-in-run routes, accept `REFERENCE_READY` only when runtime monitoring evidence is also recorded, including reviewed timeout, no-progress threshold, progress or tail log, host resource snapshot, and termination reason when the process was externally terminated or timed out. The accepted provenance class must be one of `static_author_artifact`, `native_author_workflow_run`, `native_package_api_call`, or `native_runtime_export`; the primary artifact must not be generated by BioHarness Layer3/4 surface execution or bridge replay.

Accept generated-in-run `REFERENCE_READY` only when `author_parameter_fidelity` is present and `fidelity_status` is one of `exact_match`, `runtime_only_adjusted`, or `reviewed_output_affecting_adjusted`.

Accept `REFERENCE_FAIL` only when `failure_evidence` is complete and shows that planning requirement review, author locator inspection, static artifact search/read attempt when applicable, native workflow/API execution attempt when applicable, export/parser attempt when applicable, and retry evidence for simple local issues were recorded. When failure involves missing native author input layout, accept it only if lightweight materialization was attempted or the evidence explains why materialization would exceed the reviewed boundary.

For no-target failures, accept `REFERENCE_FAIL` without native workflow execution only when `failure_evidence.target_discovery_attempt.decision` records failed target selection, rejected candidates are present, and `native_workflow_attempt.required: false` is recorded.

Accept a method result only when `stage_handoff_evidence` records the instantiated method prompt path, the Stage1 validation input preparation result path, and the canonical input path used for native/static reference acquisition.

Return `REPAIR_REQUIRED` when `stage_handoff_evidence` is absent, incomplete, not traceable to Stage1 method evidence, or replaced by an unreviewed method-specific input source.

Return `REPAIR_REQUIRED` when the method result stops after target discovery, command discovery, expected path discovery, or repair-target writing without static read/load evidence or native run evidence.

Return `REPAIR_REQUIRED` when `generation_evidence.status` is `not_run_in_stage2` or equivalent.

Return `REPAIR_REQUIRED` when `failure_evidence` is absent, incomplete, or only states the next step to run.

Return `REPAIR_REQUIRED` when a simple local path, working-directory, output-directory, lightweight native input layout materialization issue, parser, loader, or export-only issue stops the run without retry evidence.

Return `REPAIR_REQUIRED` when locator inspection is missing or ambiguous.

Return `REPAIR_REQUIRED` when the selected target is not justified by author workflow, example, vignette, or source evidence.

Return `REPAIR_REQUIRED` when a planning or handoff expected target is treated as already reviewed.

Return `REPAIR_REQUIRED` when an input sidecar, coordinate table, annotation, ground truth, config, or plot-only artifact is used as the primary output without author evidence.

Return `REPAIR_REQUIRED` when a static, generation, or export route lacks real read, run, export, or parser evidence.

Return `REPAIR_REQUIRED` when a static reference is described but no actual local read or load evidence is recorded.

Return `REPAIR_REQUIRED` when a generated reference route lacks command, working directory, environment, return code, log, produced artifact, or parser evidence. If the generated route uses native layout materialization, return `REPAIR_REQUIRED` when `native_input_layout_materialization` evidence is missing. For long-running generated-in-run routes, return `REPAIR_REQUIRED` when runtime monitoring evidence is missing, including reviewed timeout, no-progress threshold, progress or tail log, host resource snapshot, or termination reason for an externally terminated or timed-out process.

Return `REPAIR_REQUIRED` when a generated reference route changes output-affecting author parameters without reviewed acceptance, including training epochs, batch size, learning rate, model dimensions, preprocessing thresholds or preprocessing parameter values, cluster number, resolution, K, random seed value or seed-selection policy, or augmentation probabilities.

Return `REPAIR_REQUIRED` when an author CUDA training route falls back to CPU after CUDA OOM without recorded GPU memory repair attempts or a documented reason why GPU repair was not applicable.

Return `REPAIR_REQUIRED` when a generated GPU training reference changes batch size after CUDA OOM but does not record `gpu_resource_retry_evidence`, selected batch-size rationale, and preserved author parameters.

Return `REPAIR_REQUIRED` when training epochs are reduced for accepted reference acquisition, unless the reduced-epoch run is clearly marked diagnostic and a separate accepted native/static acquisition exists.

Return `REPAIR_REQUIRED` when a copied-source compatibility patch is used but `compatibility_patch_evidence` is absent, lacks diff/log paths, modifies the reviewed author source repository, or does not explain why the patch is runtime-only.

Return `REPAIR_REQUIRED` when a compatibility patch changes the selected primary target, author workflow input, algorithm branch, core algorithm call, output-affecting parameter values, or label alignment logic.

Return `REPAIR_REQUIRED` when preprocessing code is patched without preprocessing parameter consistency evidence that author preprocessing parameters were preserved.

Return `REPAIR_REQUIRED` when a result claims reviewed-prefix environment failure but records only a bare executable check and does not test the complete reviewed runtime invocation with required environment variables.

Return `REPAIR_REQUIRED` when an expected path, documentation statement, locator, or command string is treated as acquired reference evidence.

Return `REPAIR_REQUIRED` when the primary reference artifact comes from a BioHarness Layer3 callable chain, Layer4 wrapper path, bridge replay, method harness run, or execution-surface driver.

Return `REPAIR_REQUIRED` when command evidence contains Stage 3 surface-chain invocation but no native/static author acquisition evidence.

Return `REPAIR_REQUIRED` when target discovery comes from author evidence but acquisition comes from a BioHarness surface; require native/static acquisition repair.

Return `REPAIR_REQUIRED` when an auxiliary artifact replaces the primary target outside the discovered fallback policy.

Return `REPAIR_REQUIRED` when export-only wrapping is used without discovered scope evidence.

Return `REPAIR_REQUIRED` when legacy absence evidence is recorded without complete `failure_evidence`.
